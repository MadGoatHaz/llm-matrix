# The Data API

The Local AI Stack is a static site — its "API" is the JSON it publishes.
This directory is the **versioned, stable contract** for that data: every
file here is generated by the pipeline, committed to the repo, and served
by GitHub Pages at a fixed URL. Use it from scripts, other websites,
research notebooks, or your own tools.

**Live documentation page:** <https://madgoathaz.github.io/llm-matrix/api/>

---

## The endpoints

| Path | Contents | Notes |
|------|----------|-------|
| `/data.json` | The canonical submissions dataset | What the site's own client tools fetch. Carries the `version` field. |
| `/data/api/v1/submissions.json` | Identical to `/data.json` | The versioned path — the stable URL to code against. |
| `/data/api/v1/schema.json` | The JSON Schema (draft 2020-12) for the submissions payload | **Authored by hand** (not generated) — it *defines* the contract. |
| `/data/api/v1/benchmarks.json` | Benchmark reports from the Crucible thread | `{version, source, thread_id, url, count, items[]}` |
| `/data/api/v1/hardware.json` | Hardware showcases from the "Show Off Your AI Rig" thread | Same envelope as benchmarks |

All URLs are absolute from the site root, e.g.:

```
https://madgoathaz.github.io/llm-matrix/data/api/v1/submissions.json
```

## The submissions payload

Top level (all seven keys required):

| Field | Type | Meaning |
|-------|------|---------|
| `version` | string | The API version (`major.minor`) — currently `1.2`. |
| `generated_at` | string (ISO 8601) | When the pipeline last produced this dataset. |
| `schema_version` | string | The `tools/schema.json` version the data was parsed against. |
| `source_thread` | string (URL) | The forum thread the data came from. |
| `total_submissions` | integer | Must equal `len(submissions)`. |
| `skipped_templates` | integer | Unfilled template posts excluded from `submissions`. |
| `submissions` | array | The records — see below. |

Each submission record (21-key canonical shape; the full formal definition
is [`v1/schema.json`](v1/schema.json)):

| Field | Type | Meaning |
|-------|------|---------|
| `id` | string | Stable unique ID: `post_<n>_<username>_<i>`. |
| `source` | object | `{post_number, post_id, username, submitted_at, marked}` — provenance + credit. `marked` is `false` for entries recovered from an unmarked structured post (v1.2). |
| `type` | string | `"full"` (complete template) or `"quick"` (minimal report). |
| `raw` | object | The original `[COMMUNITY-SUBMISSION]` block, verbatim. For provenance — use the normalized fields. |
| `tier` | string or null | VRAM tier `t1`…`t6` (≤16GB → 196-256GB+). `null` = no VRAM tier (e.g. a CPU-only rig); renders under the matrix's "Unclassified" group (v1.2). |
| `hardware` | object | `{description, vendor}` — free text + `NVIDIA`/`AMD`/`Apple`/`Intel`/`Mixed`. |
| `backend` | string | Inference engine as reported (leading token is canonical: `vLLM (…MTP=8)` → `vLLM`). |
| `os_driver` | string | OS / driver stack as reported (e.g. `Linux/ROCm`, `Windows 11 Pro + WSL2/Ubuntu 24.04`); `""` = unreported. Displayed in the matrix detail panel. (Added in v1.1.) |
| `model` | object | `{name, url}`. |
| `quant` | string | e.g. `GGUF Q4_K_M`, `FP8`, `I-Nano`. |
| `weight_precision` | string | e.g. `~2.5bpw`. |
| `use_cases` | string | Free text (the site normalizes it against the schema's categories). |
| `context` | object | `{stable, kv_cache}`. |
| `performance` | object | `{decode_tps, prefill_tps, ttft_cold, power_w}` — strings, as reported. |
| `engine_mode` | string | `""` (unreported) / `VRAM-only` / `Hybrid (VRAM+RAM)` / `Hybrid (VRAM+RAM+SSD)` / `CPU+GPU` / `CPU-only`. |
| `notes` | string | The submitter's notes. |
| `confidence` | string | `op-verified` / `community-verified` / `community-reported` / `unverified`. |
| `lifecycle` | string | `current` / `watch` / `superseded` / `discontinued`. |
| `highlight` | boolean | Curator flag. |
| `tags` | string[] | Curator tags. |
| `inherited_from` | object | *(optional, v1.2)* Provenance for fields inherited from the post's primary block (cross-block inheritance): a map of field → source block id, e.g. `{"hardware": "block_0"}`. Present only when the block omitted hardware/backend/quant its post's primary block supplied. |

> **Honesty note:** the performance and context fields are *community-
> reported strings*, not lab measurements — that's the nature of the data.
> They're free text on purpose (people report "54.4 decode" or "19.3s");
> parse the leading number when you need one.

## The JSON Schema

[`v1/schema.json`](v1/schema.json) is a [JSON Schema
(draft 2020-12)](https://json-schema.org/draft/2020-12) describing the
submissions payload exactly: required keys, types, and the closed enums
(tiers, vendors, use of `full`/`quick`, confidence, lifecycle, engine
modes). Validate your copy against it:

```bash
# With the Python `jsonschema` package:
python3 -c "import json, jsonschema; \
  jsonschema.validate(json.load(open('data.json')), \
  json.load(open('data/api/v1/schema.json')))"
```

The repo's own test suite (`tests/test_api.py`) runs a stdlib-only
conformance check of `data.json` against the schema on every CI run.

## Versioning

- The version is `major.minor`, stamped in the `version` field of every
  payload and in the path (`v1/`).
- **Additive changes** (new optional field, new enum value) bump the
  *minor* in place: `1.0` → `1.1`, same `v1/` path.
- **Breaking changes** (removed/renamed field, type change, semantics
  change) bump the *major*: `1.0` → `2.0`, published under a **new
  `data/api/v2/` path**. `v1/` files stay frozen so existing consumers
  never break silently.
- The changelog is below. If you build on this data, pin the major version
  in your code and check `version` at runtime.

 ### Changelog

 - **v1.2 — 2026-10-13** — additive P1 data-recovery fields: `source.marked`
   (`false` for entries recovered from an unmarked structured post), the
   optional `inherited_from` provenance map (cross-block inheritance), and
   `tier` now accepts `null` (a CPU-only rig has no VRAM tier and renders
   under the matrix's "Unclassified" group). Same `v1/` path.
 - **v1.1 — 2026-10-13** — added the optional `os_driver` field to each
  submission record (OS / driver stack, shown in the detail panel);
  placeholder template values are now blanked across every field, and
  compound speed strings ("PP 120t/s, TG 2.5 t/s") are split into
  `prefill_tps` / `decode_tps` at parse time.
- **v1.0 — 2026-10-12** — initial publication: versioned `data.json`
  (`version` field added), `v1/submissions.json`, `v1/schema.json`
  (JSON Schema draft 2020-12), `v1/benchmarks.json`, `v1/hardware.json`.

## Update cadence

The data is refreshed by the **automated weekly pull**
(`.github/workflows/weekly-pull.yml`, Mondays 06:00 UTC): it fetches the
monitored forum threads, runs the parse pipeline, validates data quality,
regenerates every published file, and commits the result. New community
submissions therefore appear here **within a week** of being posted —
check `generated_at` to see the age of any copy you fetch.

## Using it from your own site (CORS)

GitHub Pages serves every file — including these JSON files — with
`Access-Control-Allow-Origin: *`, so a page on *any* domain can fetch them
directly from the browser:

```js
const res = await fetch("https://madgoathaz.github.io/llm-matrix/data.json");
const data = await res.json();
console.log(data.version, data.submissions.length);
```

Verify the header yourself at any time:

```bash
curl -sI https://madgoathaz.github.io/llm-matrix/data.json | grep -i access-control
# → access-control-allow-origin: *
```

No server, no auth, no rate-limiting contract beyond "be a good citizen" —
cache the response (it changes at most weekly).

From the command line:

```bash
curl -s https://madgoathaz.github.io/llm-matrix/data.json | python3 -m json.tool
```

From Python:

```python
import json, urllib.request
with urllib.request.urlopen(
    "https://madgoathaz.github.io/llm-matrix/data.json") as r:
    data = json.load(r)
```

## What's *not* here

- No server, no auth, no webhooks, no writes — this is static JSON on a CDN.
- No SLA: it's a community project. If you need guaranteed availability,
  mirror it (it's one small file).
- No personal data: submissions carry forum handles and hardware specs,
  nothing else. The credit is the point.
