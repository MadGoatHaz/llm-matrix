## What this is

The site is fully static — there is no backend. The "API" is the dataset itself, published at stable URLs and regenerated by the automated weekly pull:

- <code>data.json</code> — the canonical submissions dataset (what the site's own tools use)
- <code>data/api/v1/submissions.json</code> — the same payload at its **versioned** path
- <code>data/api/v1/schema.json</code> — the **JSON Schema** (draft 2020-12) that formally defines the shape
- <code>data/api/v1/benchmarks.json</code> / <code>data/api/v1/hardware.json</code> — the secondary community datasets

The full contract — every field, the versioning policy, the changelog — is documented in the <a href="https://github.com/MadGoatHaz/llm-matrix/blob/main/data/api/README.md" target="_blank" rel="noopener">API README</a> in the repo.

## The shape of a record

Each submission in <code>submissions[]</code> carries the 20-key canonical shape — provenance, hardware, OS/driver, model, quant, context, performance, and curation metadata:

```json
{
  "version": "{{api_version}}",
  "generated_at": "{{generated_at}}",
  "schema_version": "{{schema_version}}",
  "source_thread": "https://forum.level1techs.com/t/256443",
  "total_submissions": {{submission_count}},
  "skipped_templates": {{skipped_templates}},
  "submissions": [
    {
      "id": "post_2_madgoat_1",
      "source": { "post_number": 2, "post_id": 4119054, "username": "MadGoat" },
      "type": "full",
      "tier": "t1",
      "hardware": { "description": "1x Radeon VII 16GB HBM2 …", "vendor": "AMD" },
      "backend": "llama-swap (llama.cpp subprocess, ROCm)",
      "os_driver": "Linux/ROCm",
      "model": { "name": "samuelcardillo/Carnice-Qwen3.6-MoE-35B-A3B" },
      "quant": "GGUF I-Nano",
      "context": { "stable": "65536 tokens", "kv_cache": "Q8_0 (quantized)" },
      "performance": { "decode_tps": "54.4 decode", "prefill_tps": "215" }
    }
  ]
}
```

(abbreviated — the <a href="../data/api/v1/schema.json">schema</a> defines every field, type, and closed enum precisely.)

## Versioning

The <code>version</code> field is a <code>major.minor</code> stamp. **Additive** changes (new optional fields, new enum values) bump the minor in place; **breaking** changes bump the major and publish under a new <code>data/api/vN/</code> path — old versions stay frozen, so your code never breaks silently. Pin the major and check <code>version</code> at runtime.

## Use it from your own site

GitHub Pages serves every file with <code>Access-Control-Allow-Origin: *</code>, so any page on any domain can fetch the data straight from the browser:

```js
const res = await fetch("https://madgoathaz.github.io/llm-matrix/data.json");
const data = await res.json();
console.log(data.version, data.submissions.length);
```

The data changes at most weekly (the automated pull runs Mondays), so cache it.

## The honest part

The performance and context fields are **community-reported strings**, not lab measurements — "54.4 decode" is what a person typed, and that's the point of the project: real people, real hardware, real numbers. Parse the leading number when you need one; treat <code>confidence</code> as your quality signal.
